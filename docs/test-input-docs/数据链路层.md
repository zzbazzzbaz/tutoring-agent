# 数据链路层

## 一、数据链路层概述

### 1.1 数据链路层的基本概念

数据链路层（Data Link Layer）是 OSI 参考模型的第二层，位于物理层和网络层之间。数据链路层的基本功能是在相邻节点（node-to-node）之间可靠地传输数据。这里的"相邻节点"是指通过物理链路直接相连的两个节点，如主机到交换机、交换机到交换机、路由器到路由器等。

需要区分几个重要概念：
- **链路（Link）**：从一个节点到相邻节点的一段物理线路（有线或无线），中间没有任何其他交换节点。
- **数据链路（Data Link）**：在链路基础上，加上实现通信协议的硬件和软件，就构成了数据链路。数据链路就像一个数字管道。
- **帧（Frame）**：数据链路层的数据传输单元。数据链路层将网络层交下来的 IP 数据报封装成帧进行传输。

### 1.2 数据链路层提供的服务

数据链路层为网络层提供以下几种类型的服务：

1. **无确认的无连接服务**：源机器直接向目的机器发送帧，不需要先建立连接，目的机器也不需要对收到的帧进行确认。适用于误码率很低的链路（如光纤）或实时通信（如语音）。以太网提供的就是这种服务。

2. **有确认的无连接服务**：源机器不需要先建立连接就发送帧，但目的机器需要对收到的帧进行确认。如果源机器在一定时间内未收到确认，则重发该帧。适用于无线网络等不可靠的链路。802.11 Wi-Fi 就使用这种服务。

3. **有确认的面向连接服务**：源机器和目的机器在传输数据前先建立连接，传输过程中对每个帧进行确认，传输完毕后释放连接。适用于高误码率的链路或对可靠性要求很高的场景。

### 1.3 数据链路层的三个基本问题

数据链路层的功能可以概括为以下三个基本问题：

1. **封装成帧**：将网络层交下来的数据加上帧首部和帧尾部，构成一个帧。
2. **透明传输**：无论什么比特组合的数据，都能在链路上正确传输。
3. **差错检测**：检测帧在传输过程中是否发生了错误。

此外，数据链路层还需要实现流量控制和介质访问控制等功能。

## 二、封装成帧

### 2.1 帧定界

封装成帧是在一段数据的前后分别添加首部和尾部，构成一个完整的帧。帧的首部和尾部中包含重要的控制信息，其中首部和尾部的一个重要作用就是进行**帧定界**（即确定帧的边界）。

不同的数据链路层协议使用不同的帧定界方式：

- **PPP 协议**使用标志字段 `0x7E` 作为帧定界符，位于帧的首部和尾部。
- **以太网 V2** 的 MAC 帧不需要帧定界符，它通过帧间间隔（IFG，Inter-Frame Gap，96 比特时间）来分隔相邻的帧。同时在帧的前面添加 8 字节的前导码（7 字节前同步码 + 1 字节帧起始定界符 SFD），帮助接收端实现时钟同步和帧的定位。

### 2.2 透明传输

透明传输是指无论数据中出现什么样的比特组合，都不会影响帧的定界。也就是说，数据中不应该出现与帧定界符相同的比特组合，否则就会导致错误的帧定界。

#### 2.2.1 面向字节的物理链路

在面向字节的链路上（如 PPP 协议），帧定界符是 `0x7E`。如果数据中恰好出现了 `0x7E` 这个字节，接收端就会误认为这是帧的边界。

解决方法是**字节填充（Byte Stuffing）**，也称字符填充。在 PPP 协议中：

- 将信息字段中出现的每一个 `0x7E` 字节转变为 2 字节序列 `0x7D 0x5E`。
- 将信息字段中出现的每一个 `0x7D` 字节转变为 2 字节序列 `0x7D 0x5D`。
- 如果信息字段中出现 ASCII 码的控制字符（即数值小于 0x20 的字符），则在该字符前面加入一个 `0x7D` 字节，同时将该字符的编码加以改变。

通过字节填充，接收端可以正确地识别真正的帧定界符，实现透明传输。

#### 2.2.2 面向比特的物理链路

在面向比特的链路上（如 HDLC 协议），帧定界符是 `01111110`（即 `0x7E`）。如果数据中出现了连续的 6 个"1"，就可能与帧定界符混淆。

解决方法是**比特填充（Bit Stuffing）**：发送端在数据字段中，每当出现连续 5 个"1"时，就插入一个"0"。接收端在接收数据时，每当看到连续 5 个"1"后面的"0"就将其删除，恢复原始数据。

例如，数据为 `011111101`，经过比特填充后变为 `011111010 1`（在 5 个"1"后插入了一个"0"）。

### 2.3 帧的组成

一个典型的帧由以下几部分组成：

```
+--------+----------+---------+--------+
| 帧首部 | 载荷数据  | 帧尾部   |        |
+--------+----------+---------+--------+
```

- **帧首部**：包含源地址、目的地址、控制信息等。
- **载荷数据**：网络层交下来的数据（如 IP 数据报），也称为 MTU（Maximum Transmission Unit）限制范围内的数据。
- **帧尾部**：包含差错校验码（如 FCS）等。

帧的总长度有上限限制（MTU），如以太网的 MTU 为 1500 字节。如果 IP 数据报的长度超过 MTU，则需要进行分片。

## 三、差错控制

数据在传输过程中，由于噪声干扰等原因，可能会出现差错。差错控制包括差错检测和差错纠正两个方面。

### 3.1 差错的类型

- **单比特差错**：在给定的数据单元中，只有一个比特发生了改变。
- **突发差错**：在给定的数据单元中，有两个或两个以上连续的比特发生了改变。突发差错的影响可能跨越多个比特，其严重程度取决于突发长度和每个比特发生改变的概率。

在物理线路上，突发差错比单比特差错更常见。

### 3.2 循环冗余校验（CRC）

循环冗余校验（Cyclic Redundancy Check, CRC）是一种广泛使用的差错检测方法，具有很强的检错能力。

#### 3.2.1 CRC 的基本原理

CRC 的基本思想是：将要发送的数据看作一个大的二进制数，用一个预定的"生成多项式"（Generator Polynomial）去除这个数，得到的余数就是 CRC 校验码（FCS，Frame Check Sequence）。将 FCS 附加在数据后面一起发送。接收端用同样的生成多项式去除收到的数据（包括 FCS），如果余数为 0，则认为数据没有差错；否则认为数据出现了差错。

#### 3.2.2 CRC 的计算步骤

1. 发送端和接收端事先约定一个生成多项式 G(x)，其最高次幂为 r。
2. 在要发送的数据 M 后面添加 r 个 0，得到 M'。
3. 用 M' 除以 G(x)（模 2 除法，即异或运算），得到余数 R（r 位）。
4. 将余数 R 附加在数据 M 后面，构成发送的数据帧 M + R。
5. 接收端收到数据后，用收到的全部数据除以 G(x)，如果余数为 0，则无差错；否则有差错。

#### 3.2.3 模 2 运算

CRC 中的除法使用的是模 2 运算，即不借位的二进制除法，实际上是异或（XOR）运算。在模 2 运算中，加法和减法都是异或运算，没有进位和借位。

#### 3.2.4 常用的生成多项式

- **CRC-16**：G(x) = x¹⁶ + x¹⁵ + x² + 1，用于 HDLC。
- **CRC-32**：G(x) = x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1，用于以太网。
- **CRC-CCITT**：G(x) = x¹⁶ + x¹² + x⁵ + 1。

CRC 能够检测以下类型的差错：
- 所有奇数个比特的差错。
- 所有双比特差错。
- 所有长度小于等于 r（生成多项式最高次幂）的突发差错。
- 大部分长度等于 r+1 的突发差错。

CRC 只能检测差错，不能纠正差错。当检测到差错时，通常的处理方式是丢弃该帧（对于无确认的无连接服务），或请求重传（对于有确认的服务）。

### 3.3 海明码（Hamming Code）

海明码是一种前向纠错（FEC）编码，不仅能检测差错，还能纠正单比特差错。

#### 3.3.1 海明码的基本原理

海明码的核心思想是在数据位中插入若干校验位，每个校验位负责检查一组特定的数据位。通过多个校验位的组合，可以精确定位发生差错的比特位置，从而进行纠正。

#### 3.3.2 海明距离

海明距离（Hamming Distance）是指两个等长二进制串之间对应位不同的位数。例如，`0110` 和 `1001` 的海明距离为 4。

一种编码的检错和纠错能力与编码的海明距离有关：
- 要检测 d 个差错，编码的海明距离至少需要 d+1。
- 要纠正 d 个差错，编码的海明距离至少需要 2d+1。

#### 3.3.3 海明码的构造

对于 m 位数据位，需要 r 位校验位，满足：

> **2^r ≥ m + r + 1**

校验位放在 2 的幂次位置（第 1, 2, 4, 8, 16, ... 位），数据位放在其他位置。

每个校验位负责检查所有位置号的二进制表示中对应位为 1 的位置。例如：
- 校验位 P1（位置 1）检查位置 1, 3, 5, 7, 9, 11, ...（二进制最低位为 1 的位置）
- 校验位 P2（位置 2）检查位置 2, 3, 6, 7, 10, 11, ...（二进制第 2 位为 1 的位置）
- 校验位 P4（位置 4）检查位置 4, 5, 6, 7, 12, 13, 14, 15, ...
- 校验位 P8（位置 8）检查位置 8, 9, 10, 11, 12, 13, 14, 15, ...

接收端通过计算各校验位的校验结果，组成一个"症候"（Syndrome），该症候的值指示了差错的位置。如果症候为 0，表示无差错；如果症候不为 0，则其值就是出错比特的位置号，将该比特取反即可纠正差错。

海明码能够纠正单比特差错，检测双比特差错（但无法纠正双比特差错）。对于突发差错，可以通过交织技术将突发差错分散为单比特差错来处理。

## 四、流量控制

流量控制是控制发送方的发送速率，使其不超过接收方的处理能力，从而防止接收方缓冲区溢出导致数据丢失。

### 4.1 停止-等待协议（Stop-and-Wait）

停止-等待协议是最简单的流量控制协议。

#### 工作原理：
1. 发送方发送一帧后，停止发送，等待接收方的确认（ACK）。
2. 接收方收到帧后，进行差错检测。如果正确，返回确认（ACK）；如果有错，可以不返回任何信息，或返回否认（NAK）。
3. 发送方收到 ACK 后，发送下一帧。
4. 如果发送方在一定时间内未收到确认（超时），则重发该帧。

#### 需要解决的问题：

1. **帧丢失**：发送方发送的数据帧丢失，发送方超时后重发。
2. **确认丢失**：接收方的确认丢失，发送方超时后重发。但接收方可能收到重复帧，因此需要**帧编号**来区分。在停止-等待协议中，帧编号只需要 0 和 1 两个值（交替使用）即可。
3. **确认迟到**：确认迟到导致发送方超时重发，之后又收到了迟到的确认。发送方需要忽略迟到的确认。

#### 停止-等待协议的特点：
- 实现简单。
- 信道利用率低，因为每次只发送一帧就要等待确认。
- 适用于传播延迟小、数据帧较长的场景。

信道利用率公式：

> **U = t_f / (t_f + 2 × t_p + t_a)**

其中 t_f 为发送数据帧的时间，t_p 为单程传播延迟，t_a 为发送确认帧的时间。当 t_a 很小时：

> **U ≈ t_f / (t_f + 2 × t_p)**

### 4.2 后退 N 帧协议（Go-Back-N, GBN）

后退 N 帧协议（也称连续 ARQ 协议）允许发送方在未收到确认的情况下连续发送多个帧，从而提高信道利用率。

#### 工作原理：
1. 发送方维护一个发送窗口，窗口大小为 N。窗口内的帧可以连续发送，无需等待确认。
2. 发送方为每个帧编号，编号使用模 2^n（n 为序号字段比特数）。
3. 接收方采用**累积确认**方式：收到帧后，返回对按序到达的最后一个帧的确认。例如，接收方已正确接收帧 0、1、2、3，则返回 ACK 3（表示期望下一帧是 4，帧 0~3 均已正确接收）。
4. 接收方只按序接收帧。如果收到乱序帧（如期望帧 3 但收到帧 4），则丢弃帧 4，并重新发送最后按序确认的 ACK。
5. 如果发送方对某帧的超时定时器到期，则从该帧开始，**重发所有已发送但未确认的帧**（即后退 N 帧）。

#### GBN 的特点：
- 提高了信道利用率。
- 接收方不需要缓存乱序帧，实现简单。
- 当差错率较高时，重传量大，效率下降明显。
- 窗口大小 N 的选择需要考虑传播延迟和带宽的乘积（带宽延迟积）。

#### GBN 的窗口大小限制：
- 发送窗口 W ≤ 2^n - 1（n 为序号比特数）。这个限制是为了避免序号混淆。例如，当 n=2 时，窗口大小最大为 3。如果窗口为 4，则发送帧 0、1、2、3 后，接收方返回 ACK 3，但这个 ACK 也可能表示"之前的全部 0~3 都丢失了，请重发"，从而产生歧义。

### 4.3 选择重传协议（Selective Repeat, SR）

选择重传协议进一步提高了效率，它只重传出错或丢失的帧，而不是从出错帧开始的所有帧。

#### 工作原理：
1. 发送方维护一个发送窗口，窗口大小为 W_s。
2. 接收方维护一个接收窗口，窗口大小为 W_r。接收方可以接收窗口内的乱序帧，并缓存它们。
3. 接收方对正确收到的每个帧独立确认（不再使用累积确认）。
4. 当某个帧的定时器超时，发送方只重传该帧。
5. 当接收窗口中的帧按序完整后，将数据交付给上层，接收窗口向前滑动。

#### SR 的特点：
- 重传量小，效率高，尤其在差错率较高的链路上。
- 接收方需要较大的缓冲区来缓存乱序帧。
- 实现复杂度高于 GBN。

#### SR 的窗口大小限制：
- 发送窗口和接收窗口之和应满足：**W_s + W_r ≤ 2^n**（n 为序号比特数）。
- 通常取 W_s = W_r = 2^(n-1)，即各为序号空间的一半。

### 4.4 三种流量控制协议的比较

| 特性 | 停止-等待 | 后退 N 帧（GBN） | 选择重传（SR） |
|------|----------|-----------------|--------------|
| 发送窗口 | 1 | N | W_s |
| 接收窗口 | 1 | 1 | W_r |
| 确认方式 | 单帧确认 | 累积确认 | 独立确认 |
| 出错处理 | 重发当前帧 | 后退 N 帧重发 | 只重发出错帧 |
| 接收方缓存 | 不需要 | 不需要 | 需要 |
| 信道利用率 | 最低 | 较高 | 最高 |
| 实现复杂度 | 最简单 | 较简单 | 最复杂 |

## 五、介质访问控制（MAC）

介质访问控制（Medium Access Control, MAC）是数据链路层的一个子层，负责解决多个节点共享同一信道时的信道分配问题。MAC 子层的任务是决定谁可以在什么时候使用信道。

### 5.1 信道分配方式

1. **静态分配**：如 FDM、TDM，预先为每个用户分配固定的频带或时隙。适用于用户数量少且固定、流量稳定的场景。当用户数量多且流量突发性强时，静态分配效率低下。

2. **动态分配**：按需分配信道资源，如随机接入协议（ALOHA、CSMA 系列）和受控接入协议（轮询、令牌传递）。

### 5.2 ALOHA 协议

#### 5.2.1 纯 ALOHA

纯 ALOHA 是最早的随机接入协议，由夏威夷大学在 1970 年代提出。其基本思想是：当任何站点有数据要发送时，就直接发送。如果发生碰撞（冲突），则等待一段随机时间后重发。

纯 ALOHA 的性能：
- 最大吞吐量（信道利用率）约为 18.4%（在 G=0.5 时达到）。
- 其中 G 为每个帧时间内的平均发送帧数。

#### 5.2.2 时隙 ALOHA

时隙 ALOHA 是纯 ALOHA 的改进版本。它将时间划分为等长的时隙，每个时隙正好可以发送一个帧。站点只能在时隙的开始时刻发送数据，不能在任意时刻发送。

时隙 ALOHA 的改进效果：
- 碰撞只可能发生在时隙开始处，碰撞窗口从纯 ALOHA 的 2 个帧时间减少到 1 个帧时间。
- 最大吞吐量约为 36.8%（在 G=1 时达到），是纯 ALOHA 的两倍。

### 5.3 CSMA（载波监听多路访问）

CSMA（Carrier Sense Multiple Access）在 ALOHA 的基础上增加了"载波监听"功能：站点在发送数据前，先监听信道，如果信道忙（有其他站点在发送），则等待；如果信道空闲，才发送数据。

CSMA 的几种策略：

1. **1-坚持 CSMA（1-persistent CSMA）**：站点监听信道，如果忙，则持续监听（坚持等待）；一旦信道空闲，立即发送（以概率 1 发送）。缺点是：如果两个或多个站点同时在等待，信道空闲时它们会同时发送，导致碰撞。

2. **非坚持 CSMA（Non-persistent CSMA）**：站点监听信道，如果忙，则不再持续监听，而是等待一段随机时间后再监听。优点是减少了碰撞概率；缺点是信道空闲后可能需要等待一段时间才被利用，增加了延迟。

3. **p-坚持 CSMA（p-persistent CSMA）**：适用于时隙信道。站点监听信道，如果忙，则持续监听；如果空闲，则以概率 p 发送数据，以概率 (1-p) 延迟到下一个时隙再监听。折中了 1-坚持和非坚持的优缺点。

CSMA 虽然在发送前进行了载波监听，但由于信号传播延迟的存在，仍然可能发生碰撞。当站点 A 开始发送数据后，信号需要经过一定的传播时间才能到达站点 B。在这段时间内，站点 B 监听信道发现空闲，也会发送数据，从而导致碰撞。

### 5.4 CSMA/CD（载波监听多路访问/碰撞检测）

CSMA/CD（Carrier Sense Multiple Access with Collision Detection）是在 CSMA 基础上增加了**碰撞检测**功能，主要用于有线以太网（IEEE 802.3）。

#### 5.4.1 工作流程

CSMA/CD 的工作流程可概括为：**先听后发，边发边听，冲突停发，随机重发**。

1. **先听后发**：发送前先监听信道，如果信道空闲，开始发送；如果忙，则等待。
2. **边发边听**：发送数据的同时继续监听信道，检测是否发生碰撞。
3. **冲突停发**：一旦检测到碰撞，立即停止发送数据，并发送一个拥塞信号（Jam Signal）使所有站点都知道发生了碰撞。
4. **随机重发**：采用截断二进制指数退避算法，等待一段随机时间后重新尝试发送。

#### 5.4.2 碰撞检测的原理

碰撞检测是通过比较发送的信号和接收到的信号来实现的。如果接收到的信号与发送的信号不一致（如信号电压异常增大），说明发生了碰撞。

碰撞检测要求：站点在发送数据的过程中，必须能够检测到碰撞。这意味着帧的发送时间必须大于信号在网络中往返传播的时间（2τ，τ 为单程传播延迟）。由此引出**最小帧长**的概念：

> **最小帧长 = 2 × 传播延迟 × 数据传输速率**

以太网规定最小帧长为 **64 字节**。如果数据不足 64 字节，需要填充（Padding）到 64 字节。这个最小帧长的规定保证了在冲突检测窗口内（2τ 时间内），发送方一定能检测到碰撞。

#### 5.4.3 争用期

以太网的端到端往返时间 2τ 称为**争用期**（Contention Period），也称碰撞窗口。以太网取 51.2 μs 作为争用期。对于 10 Mbit/s 以太网，争用期内可发送 512 比特 = 64 字节，这就是最小帧长的由来。

#### 5.4.4 截断二进制指数退避算法

发生碰撞后，站点不是立即重发，而是等待一段随机时间。随机时间的确定采用截断二进制指数退避算法：

1. 确定基本退避时间，通常为争用期 2τ。
2. 定义参数 k，k = min(重传次数, 10)。
3. 从整数集合 {0, 1, 2, ..., 2^k - 1} 中随机选择一个数 r，退避时间 = r × 2τ。
4. 当重传次数达到 16 次仍不成功时，说明网络拥塞严重，丢弃该帧并向高层报错。

截断二进制指数退避算法的特点是：随着碰撞次数的增加，退避时间动态增大，从而在轻负载时快速重传，在重负载时减少碰撞概率。

### 5.5 CSMA/CA（载波监听多路访问/碰撞避免）

CSMA/CA（Carrier Sense Multiple Access with Collision Avoidance）主要用于无线局域网（IEEE 802.11 Wi-Fi）。

#### 5.5.1 为什么无线网络不能使用 CSMA/CD？

无线网络不使用 CSMA/CD 的原因：

1. **碰撞检测困难**：在无线环境中，发送信号的强度远大于接收信号的强度（因为发送端就在自己旁边，而接收端可能在远处），发送时很难同时检测其他站点的信号。
2. **隐藏终端问题**：站点 A 和 C 都能和站点 B 通信，但 A 和 C 互相听不到对方（由于障碍物或距离太远）。当 A 和 C 同时向 B 发送时，会在 B 处发生碰撞，但 A 和 C 无法检测到。
3. **暴露终端问题**：站点 B 在向 A 发送数据时，站点 C 想向 D 发送数据。由于 C 能听到 B 的发送，它会认为信道忙而等待。但实际上 C 向 D 发送不会影响 B 向 A 的发送，C 的等待是不必要的。

#### 5.5.2 CSMA/CA 的工作流程

CSMA/CA 采用**碰撞避免**策略：

1. **载波监听**：发送前先监听信道。如果信道空闲，等待 DIFS（DCF Interframe Space）时间后发送。
2. **RTS/CTS 机制**：为解决隐藏终端问题，可选使用 RTS/CTS（Request To Send / Clear To Send）握手。
   - 发送方发送 RTS 帧，预约信道。
   - 接收方收到 RTS 后，回复 CTS 帧。
   - 发送方收到 CTS 后，开始发送数据。
   - 隐藏终端听到 CTS 后，在数据传输期间保持静默。
3. **确认机制**：接收方正确收到数据后，等待 SIFS（Short Interframe Space）时间后返回 ACK。如果发送方未收到 ACK，则重传。
4. **退避机制**：即使信道空闲，站点也有一定概率需要执行退避（在竞争窗口内随机选择退避时间），以减少碰撞概率。

CSMA/CA 使用的帧间间隔（IFS）：
- **SIFS（Short IFS）**：最短，用于 ACK、CTS 等高优先级帧。
- **PIFS（Point Coordination IFS）**：中等，用于 PCF 模式。
- **DIFS（DCF IFS）**：最长，用于普通数据帧的发送。

## 六、局域网技术

### 6.1 局域网概述

局域网（Local Area Network, LAN）是在一个较小地理范围内（如一栋楼、一个校园）将多台计算机互连起来的网络。局域网具有覆盖范围小、传输速率高、误码率低等特点。

IEEE 802 委员会制定了一系列局域网标准，其中数据链路层被划分为两个子层：
- **逻辑链路控制子层（LLC, Logical Link Control）**：IEEE 802.2，为网络层提供统一接口。
- **介质访问控制子层（MAC, Medium Access Control）**：与具体的局域网技术相关，如 IEEE 802.3（以太网）、IEEE 802.5（令牌环）、IEEE 802.11（Wi-Fi）等。

### 6.2 以太网（IEEE 802.3）

以太网是目前最流行的局域网技术，由 IEEE 802.3 标准定义。以太网经历了从共享式到交换式的发展历程。

#### 6.2.1 以太网的帧格式

以太网 V2 的 MAC 帧格式如下：

```
+----------+----------+----------+-----------+---------+
| 前导码    | 目的地址  | 源地址    | 类型/长度  | 数据     | FCS |
| 8 字节    | 6 字节    | 6 字节    | 2 字节     | 46~1500 | 4   |
+----------+----------+----------+-----------+---------+-----+
```

各字段说明：
- **前导码（8 字节）**：7 字节前同步码（10101010...）+ 1 字节帧起始定界符 SFD（10101011），用于接收端的时钟同步和帧定位。注意：前导码不计入帧长度。
- **目的地址（6 字节）**：接收方的 MAC 地址。
- **源地址（6 字节）**：发送方的 MAC 地址。
- **类型/长度（2 字节）**：在以太网 V2 中，该字段表示上层协议类型（如 0x0800 表示 IP 协议，0x0806 表示 ARP 协议）。在 IEEE 802.3 中，该字段表示数据字段的长度。
- **数据（46~1500 字节）**：上层交下来的数据（如 IP 数据报）。最小 46 字节是为了保证帧的最小长度为 64 字节（6+6+2+46+4=64），不足 46 字节需要填充。
- **FCS（4 字节）**：帧校验序列，使用 CRC-32 校验。

#### 6.2.2 MAC 地址

MAC 地址（硬件地址、物理地址）是 48 位的地址，通常表示为 6 组十六进制数，如 `08:00:27:71:36:E2`。

MAC 地址的分类：
- **单播地址**：目的地址为特定的一台设备，地址的第一个字节的最低位为 0。
- **组播地址**：目的地址为一组设备，地址的第一个字节的最低位为 1。
- **广播地址**：目的地址为 `FF:FF:FF:FF:FF:FF`，表示发送给网络上的所有设备。

MAC 地址的第一字节的次低位（第 2 位）表示地址是全局唯一还是本地管理：
- 0：全局唯一（UAA, Universally Administered Address），由 IEEE 分配。
- 1：本地管理（LAA, Locally Administered Address），由网络管理员分配。

MAC 地址烧录在网卡的 ROM 中，通常是固定的。但现代操作系统也允许修改 MAC 地址（软件修改）。

### 6.3 交换机工作原理

交换机（Switch）是工作在数据链路层的设备，它能根据 MAC 地址转发帧，是现代局域网的核心设备。

#### 6.3.1 交换机的转发原理

交换机内部维护一张**MAC 地址表**（也称转发表、交换表），记录 MAC 地址与端口的对应关系。

交换机的工作过程：

1. **学习**：当交换机从某个端口收到一个帧时，它会将帧的源 MAC 地址与接收端口的对应关系记录到 MAC 地址表中（如果表中已有该 MAC 地址，则更新其老化时间）。这就是交换机的"自学习"功能。

2. **转发**：
   - 如果目的 MAC 地址在地址表中有记录（已知），则将帧从对应的端口转发出去（这就是**单播转发**）。
   - 如果目的 MAC 地址在地址表中没有记录（未知），则将帧从除接收端口外的所有端口转发出去（这就是**泛洪/Flooding**）。
   - 如果目的 MAC 地址与源 MAC 地址在同一个端口（表项中记录的端口与接收端口相同），则丢弃该帧（不需要转发）。

3. **广播帧处理**：如果收到广播帧（目的地址为 FF:FF:FF:FF:FF:FF），则从除接收端口外的所有端口转发出去。

#### 6.3.2 MAC 地址表的老化

交换机的 MAC 地址表中的每个条目都有一个老化时间（默认通常为 300 秒）。如果一个 MAC 地址在老化时间内没有被再次学习，该条目将被删除。这种机制使得交换机能够适应网络拓扑的变化。

#### 6.3.3 交换机的特点

- **隔离冲突域**：交换机的每个端口是一个独立的冲突域，连接在交换机上的设备可以同时收发数据，无需 CSMA/CD。
- **全双工通信**：交换机支持全双工模式，发送和接收可以同时进行。
- **存储转发**：大多数交换机采用存储转发方式，先将完整的帧接收并缓存，检查 FCS 后再转发。也有直通转发方式，只读取目的地址就开始转发，延迟更小但不检查差错。

交换机与集线器的关键区别：集线器是物理层设备，所有端口共享带宽、共享冲突域；交换机是数据链路层设备，每个端口独占带宽、独立冲突域。

## 七、虚拟局域网（VLAN）

### 7.1 VLAN 的基本概念

虚拟局域网（Virtual Local Area Network, VLAN）是通过逻辑方式而非物理方式将网络划分为多个广播域的技术。VLAN 允许将一个物理交换机上的端口划分为多个逻辑组，每个组构成一个独立的 VLAN。

VLAN 的优势：
- **限制广播域**：每个 VLAN 是一个独立的广播域，广播帧不会跨越 VLAN 传播，减少了广播流量对网络的影响。
- **提高安全性**：不同 VLAN 之间的通信需要通过路由器或三层交换机，可以实施访问控制。
- **提高灵活性**：VLAN 的划分与物理位置无关，用户可以在不同地理位置属于同一个 VLAN。
- **简化管理**：当用户移动或变更时，只需调整 VLAN 配置，无需重新布线。

### 7.2 VLAN 的划分方式

1. **基于端口的 VLAN**：将交换机的端口静态分配到不同的 VLAN。配置简单，但当用户移动到不同端口时需要重新配置。
2. **基于 MAC 地址的 VLAN**：根据网卡的 MAC 地址划分 VLAN。用户移动时无需重新配置，但管理复杂。
3. **基于协议的 VLAN**：根据网络层协议类型划分 VLAN。
4. **基于子网的 VLAN**：根据 IP 地址所在的子网划分 VLAN。

基于端口的 VLAN 是最常用的方式。

### 7.3 IEEE 802.1Q

IEEE 802.1Q 是 VLAN 的标准协议，定义了在以太网帧中插入 VLAN 标记的方法。

802.1Q 标记（Tag）插入在 MAC 帧的源地址和类型/长度字段之间，共 4 字节：

```
+----------+----------+--------+-----------+-----------+---------+-----+
| 目的地址  | 源地址    | TPID   | TCI       | 类型/长度  | 数据     | FCS |
| 6 字节    | 6 字节    | 2 字节 | 2 字节    | 2 字节     | 46~1500 | 4   |
+----------+----------+--------+-----------+-----------+---------+-----+
```

- **TPID（Tag Protocol Identifier, 2 字节）**：值为 0x8100，表示这是一个 802.1Q 标记帧。
- **TCI（Tag Control Information, 2 字节）**：
  - **优先级（Priority, 3 位）**：用于服务质量（QoS）。
  - **DEI/CFI（1 位）**：规范格式指示器。
  - **VID（VLAN Identifier, 12 位）**：VLAN 标识符，可表示 4096 个 VLAN（0 和 4095 保留，实际可用 1~4094）。

### 7.4 Trunk 链路

当多个交换机上有相同的 VLAN 时，需要通过交换机之间的链路传输多个 VLAN 的数据。这种链路称为 **Trunk 链路**（干道链路）。

- **Access 链路**：连接终端设备（如 PC）的端口，只属于一个 VLAN，帧在 Access 端口上不带 802.1Q 标记。
- **Trunk 链路**：连接交换机之间的端口，可以承载多个 VLAN 的数据，帧在 Trunk 链路上携带 802.1Q 标记（Native VLAN 除外）。

在 Trunk 链路上，交换机发送帧时会添加 802.1Q 标记（封装），接收帧时会移除标记（解封装）。通过标记中的 VID，接收方可以知道该帧属于哪个 VLAN。

### 7.5 VLAN 间通信

不同 VLAN 之间属于不同的广播域，二层设备（交换机）无法直接转发不同 VLAN 之间的数据。VLAN 间通信需要使用三层设备：

1. **通过路由器**：可以在每个 VLAN 连接一个路由器端口，或者使用"单臂路由器"（Router-on-a-Stick），通过一个物理接口上的多个子接口，使用 802.1Q 封装实现 VLAN 间路由。
2. **通过三层交换机**：三层交换机集成了二层交换和三层路由功能，通过内部的路由引擎实现 VLAN 间转发，速度快、延迟低，是现代企业网络的主流方案。

## 八、数据链路层设备

### 8.1 网桥

网桥（Bridge）是早期的数据链路层设备，工作在 MAC 子层。网桥有多个端口，每个端口连接一个网段。网桥根据 MAC 地址转发帧，可以连接不同类型的局域网。

网桥的工作原理与交换机类似：通过自学习构建转发表，根据目的 MAC 地址进行转发或过滤。网桥与交换机的主要区别在于：网桥通常端口数量少，以软件方式转发；交换机端口数量多，以硬件（ASIC）方式转发，速度更快。从功能上说，交换机可以看作是多端口网桥。

### 8.2 交换机

交换机已在上一节详细介绍，这里补充交换机的转发方式：

1. **存储转发（Store-and-Forward）**：交换机将完整的帧接收并缓存，检查 FCS 后再转发。优点是可以检测并过滤错误帧；缺点是延迟较大。
2. **直通转发（Cut-Through）**：交换机只读取帧的目的 MAC 地址（前 6 字节），就立即转发。优点是延迟小；缺点是无法检测错误帧。
3. **无碎片转发（Fragment-Free）**：存储前 64 字节后再转发，可以过滤掉冲突碎片（因为碰撞碎片通常小于 64 字节）。

### 8.3 生成树协议（STP）

#### 8.3.1 为什么需要 STP？

在交换网络中，为了提高可靠性，通常会部署冗余链路（备份链路）。但冗余链路会导致以下问题：

1. **广播风暴**：广播帧在环路中不断循环，导致网络中充满广播帧，消耗带宽和设备资源。
2. **重复帧**：同一帧可能通过不同路径被多次送达目的地。
3. **MAC 地址表不稳定**：交换机可能从不同端口收到同一源 MAC 的帧，导致地址表不断更新。

#### 8.3.2 STP 的工作原理

生成树协议（Spanning Tree Protocol, STP）由 IEEE 802.1D 标准定义。STP 通过在交换网络中构建一棵无环的生成树，将冗余链路置为阻塞状态，消除环路。当活动链路故障时，STP 可以自动激活被阻塞的链路，恢复连通性。

STP 的工作过程：

1. **选举根桥（Root Bridge）**：选择桥 ID（Bridge ID = 优先级 + MAC 地址）最小的交换机作为根桥。默认优先级为 32768。

2. **选举根端口（Root Port）**：每个非根桥交换机选择一个到根桥开销最小的端口作为根端口。根路径开销是沿途各链路开销之和。

3. **选举指定端口（Designated Port）**：每条链路上选择一个到根桥开销最小的端口作为指定端口。根桥的所有端口都是指定端口。

4. **阻塞其他端口**：既不是根端口也不是指定端口的端口被置为阻塞状态（Blocking），不转发数据帧。

STP 的端口状态：
- **阻塞（Blocking）**：只接收 BPDU，不转发数据帧。
- **监听（Listening）**：不转发数据帧，参与 STP 计算。
- **学习（Learning）**：学习 MAC 地址，但不转发数据帧。
- **转发（Forwarding）**：正常转发数据帧。

STP 的收敛时间较长，从阻塞到转发需要经历监听和学习状态，默认约 50 秒。

#### 8.3.3 STP 的改进

- **RSTP（Rapid STP, IEEE 802.1w）**：快速生成树协议，收敛时间缩短到 1~2 秒。
- **MSTP（Multiple STP, IEEE 802.1s）**：多生成树协议，可以为不同的 VLAN 组构建不同的生成树，实现负载均衡。

## 参考答案

### 选择题答案

**1. B。** 数据链路层的数据传输单元是帧（Frame）。物理层的传输单元是比特，网络层是分组（或 IP 数据报），传输层是报文段。

**2. B。** 生成多项式 G(x) = x⁴ + x + 1 的最高次幂为 4，因此 CRC 校验码（FCS）的长度为 4 位。FCS 的位数等于生成多项式的最高次幂。

**3. C。** 以太网最小帧长为 64 字节，是为了保证在冲突检测窗口（争用期 2τ）内，发送方能够检测到碰撞。如果帧太短，发送方可能在碰撞信号返回之前就已发送完毕，从而无法检测到碰撞。

**4. B。** 当交换机收到目的 MAC 地址不在地址表中的单播帧时（即未知单播帧），交换机会执行泛洪操作，将帧从除接收端口外的所有端口转发出去，以便目的设备能够收到。

**5. C。** VID 字段为 12 位，理论上有 2¹² = 4096 个取值（0~4095），但 VID 0 和 4095 被保留，实际可用的 VLAN 数量为 4094 个。题目问"最多可以定义"，答案为 4096。

### 简答题答案

**1.**

CSMA/CD（载波监听多路访问/碰撞检测）的工作原理可概括为十六个字："先听后发，边发边听，冲突停发，随机重发"。

- **先听后发**：发送前先监听信道，信道空闲则开始发送，忙则等待。
- **边发边听**：发送过程中持续监听信道，检测是否发生碰撞。
- **冲突停发**：一旦检测到碰撞，立即停止发送，并发送拥塞信号通知所有站点。
- **随机重发**：使用截断二进制指数退避算法计算等待时间，然后重新尝试发送。

最小帧长的意义：以太网规定最小帧长为 64 字节。这是为了保证在争用期（2τ，即信号在网络中往返传播的时间）内，发送方一直在发送数据，从而能够在帧发送完成之前检测到碰撞。如果帧长小于最小帧长，发送方可能在碰撞信号返回之前就已完成发送，导致无法检测到碰撞。最小帧长 = 2 × 传播延迟 × 数据传输速率。对于 10 Mbit/s 以太网，争用期为 51.2μs，最小帧长 = 10Mbit/s × 51.2μs = 512 bit = 64 字节。

**2.**

三种协议的相同点：
- 都属于自动重传请求（ARQ）协议，通过确认和重传机制实现可靠传输。
- 都使用帧编号来处理重复帧问题。
- 都有超时重传机制。

不同点：
- **发送窗口**：停止-等待协议的发送窗口为 1；GBN 的发送窗口为 N（N>1）；SR 的发送窗口为 W_s（W_s>1）。
- **接收窗口**：停止-等待和 GBN 的接收窗口均为 1（只能按序接收）；SR 的接收窗口大于 1（可接收乱序帧并缓存）。
- **确认方式**：停止-等待对每个帧单独确认；GBN 使用累积确认；SR 对每个帧独立确认。
- **出错处理**：停止-等待只重发当前帧；GBN 从出错帧开始后退重发所有后续帧；SR 只重发出错的那一帧。
- **接收方缓存**：停止-等待和 GBN 不需要缓存乱序帧；SR 需要。
- **效率**：停止-等待效率最低；GBN 较高；SR 最高。实现复杂度则相反。

**3.**

交换机的工作原理：

（1）自学习过程：当交换机从某个端口收到一个帧时，它将帧的源 MAC 地址和接收端口号的对应关系记录到 MAC 地址表中。如果该 MAC 地址已存在，则更新其老化时间。这样交换机逐渐"学习"到网络中各设备的位置。

（2）转发过程：交换机收到帧后，查找目的 MAC 地址在 MAC 地址表中的记录：
- 如果找到对应记录，且记录的端口与接收端口不同，则从对应端口转发（单播转发）。
- 如果找到记录，但记录端口与接收端口相同，则丢弃该帧（无需转发）。
- 如果没有找到记录（未知单播帧），则将帧泛洪到除接收端口外的所有端口。
- 如果是广播帧，也泛洪到除接收端口外的所有端口。

交换机与集线器的区别：
- 工作层次：集线器工作在物理层，交换机工作在数据链路层。
- 转发方式：集线器将信号广播到所有端口；交换机根据 MAC 地址表进行精准转发。
- 带宽分配：集线器的所有端口共享带宽；交换机的每个端口独占带宽。
- 冲突域：集线器的所有端口在同一个冲突域；交换机的每个端口是独立的冲突域。
- 智能性：集线器不理解帧的内容；交换机能识别 MAC 地址，支持 VLAN 等高级功能。
