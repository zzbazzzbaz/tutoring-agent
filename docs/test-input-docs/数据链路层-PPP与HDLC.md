# 数据链路层 —— PPP 与 HDLC

## 一、概述

在数据链路层中，除了局域网中广泛使用的以太网协议外，还有两种重要的点对点链路协议：**PPP（Point-to-Point Protocol，点对点协议）** 和 **HDLC（High-level Data Link Control，高级数据链路控制）**。这两种协议都用于在点对点链路上实现数据传输，但它们在设计理念、帧格式、功能特性等方面存在显著差异。

PPP 协议是目前互联网上使用最广泛的点对点数据链路层协议，广泛应用于拨号上网、宽带接入（如 PPPoE）、路由器之间的串行链路等场景。HDLC 协议是国际标准化组织（ISO）制定的标准，面向比特传输，在传统电信网络和某些专用网络中应用较多。

本文将详细介绍 PPP 和 HDLC 的协议结构、帧格式、工作机制，并对两者进行比较。关于数据链路层的一般性内容（如封装成帧、差错控制等），请参阅《数据链路层》文档。

## 二、点对点协议 PPP

### 2.1 PPP 概述

PPP（Point-to-Point Protocol）是为在点对点链路上传输多协议数据包而设计的数据链路层协议，由 RFC 1661 定义。PPP 是 Internet 工程任务组（IETF）制定的标准，用于取代早期的 SLIP（Serial Line Internet Protocol）协议。

PPP 的设计目标：
- 支持多种网络层协议（如 IP、IPX、AppleTalk 等）的多路复用。
- 支持多种类型的物理链路（如串行线、电话线、光纤、无线等）。
- 提供差错检测功能。
- 支持可选的认证功能。
- 协议结构简单，开销小。

PPP 不提供的服务：
- 纠错功能：PPP 只进行差错检测（FCS），不进行纠错。发现差错的帧直接丢弃，纠错由上层协议（如 TCP）处理。
- 流量控制：PPP 不提供流量控制，假设接收方有能力处理收到的数据。
- 按序交付：PPP 不保证帧按序到达。

### 2.2 PPP 的协议结构

PPP 协议不是一个单一的协议，而是一个协议族，由三个部分组成：

#### 2.2.1 PPP 的封装方式

PPP 提供一种将多种网络层协议数据报封装到串行链路上的方法。PPP 使用 HDLC 的变体帧格式来封装数据报，支持透明传输。

#### 2.2.2 链路控制协议 LCP（Link Control Protocol）

LCP 用于建立、配置、维护和终止数据链路连接。LCP 的主要功能包括：
- 建立数据链路连接（链路建立阶段）。
- 协商链路参数（如最大接收单元 MRU、认证协议等）。
- 测试链路质量。
- 终止链路连接。

#### 2.2.3 网络控制协议 NCP（Network Control Protocol）

NCP 是一组协议，用于配置和测试不同的网络层协议。每个网络层协议都有对应的 NCP：
- **IPCP（IP Control Protocol）**：用于配置 IP 协议，包括分配 IP 地址、协商 IP 压缩方式等。
- **IPXCP**：用于配置 IPX 协议。
- 其他 NCP 对应其他网络层协议。

NCP 的主要功能是在链路建立后，为网络层协议进行配置（如动态分配 IP 地址），使网络层协议能够在 PPP 链路上正常运行。

### 2.3 PPP 的帧格式

PPP 的帧格式基于 HDLC 帧格式，但做了一些修改。PPP 帧的格式如下：

```
+------+------+------+------+----------+------+
| 标志  | 地址  | 控制  | 协议  | 数据      | FCS  | 标志  |
| 1字节 | 1字节 | 1字节 | 2字节 | 可变长度  | 2-4  | 1字节 |
+------+------+------+------+----------+------+
```

各字段说明：

- **标志字段（Flag, 1 字节）**：值为 `0x7E`（二进制 `01111110`），用于帧定界，标志一个帧的开始和结束。

- **地址字段（Address, 1 字节）**：固定为 `0xFF`（二进制 `11111111`），表示广播地址。由于 PPP 是点对点协议，不需要寻址，因此地址字段没有实际意义，固定为全 1。

- **控制字段（Control, 1 字节）**：固定为 `0x03`（二进制 `00000011`），表示这是一个无编号帧（U 帧）。PPP 默认不使用序号和确认机制，因此使用无编号帧。

- **协议字段（Protocol, 2 字节）**：标识信息字段中封装的数据属于哪个协议。常见取值：
  - `0x0021`：IP 数据报
  - `0xC021`：LCP 数据
  - `0x8021`：IPCP（NCP 的一种）
  - `0xC023`：PAP 认证协议
  - `0xC223`：CHAP 认证协议

- **数据字段（Information, 可变长度）**：封装的上层数据，长度可变，但受到 MRU（Maximum Receive Unit，默认 1500 字节）的限制。

- **FCS 字段（Frame Check Sequence, 2 或 4 字节）**：帧校验序列，默认使用 16 位 CRC，也可以协商使用 32 位 CRC。

### 2.4 PPP 的透明传输

PPP 需要在各种链路上实现透明传输，根据链路类型的不同，采用不同的方法：

#### 2.4.1 异步传输（面向字节）

当 PPP 运行在异步串行链路上时，采用**字节填充**实现透明传输：

- 信息字段中出现的 `0x7E`（标志字段值）转变为 `0x7D 0x5E`。
- 信息字段中出现的 `0x7D`（转义字符）转变为 `0x7D 0x5D`。
- 信息字段中出现 ASCII 码的控制字符（值小于 `0x20`），在该字符前加 `0x7D`，并将该字符的编码与 `0x20` 异或。

接收端进行逆操作，恢复原始数据。

#### 2.4.2 同步传输（面向比特）

当 PPP 运行在同步串行链路上时（如 SONET/SDH 链路），采用**比特填充**实现透明传输，与 HDLC 的方法相同：

- 发送端在信息字段中，每当出现连续 5 个"1"时，就插入一个"0"。
- 接收端在接收时，每当看到连续 5 个"1"后的"0"就删除它。

### 2.5 PPP 的工作状态

PPP 链路的建立、维护和终止是一个状态转换的过程，RFC 1661 定义了 PPP 的状态机。PPP 链路的典型生命周期包括以下阶段：

#### 2.5.1 链路不可用阶段（Link Dead）

初始状态，物理层链路尚未就绪。当物理层报告链路已建立（如载波检测信号有效）时，进入链路建立阶段。

#### 2.5.2 链路建立阶段（Link Establishment）

LCP 协商阶段。双方交换 LCP 配置报文（Configure-Request、Configure-Ack、Configure-Nak、Configure-Reject），协商链路参数，如：
- MRU（最大接收单元）
- 认证协议（PAP 或 CHAP）
- 魔术字（Magic Number，用于环路检测）
- 协议字段压缩（PFC）
- 地址和控制字段压缩（ACFC）

LCP 协商成功后，如果配置了认证，进入认证阶段；否则直接进入网络层协议阶段。

#### 2.5.3 认证阶段（Authentication）

如果 LCP 协商中要求进行认证，则进入认证阶段。PPP 支持两种认证协议：PAP 和 CHAP（详见下文）。认证成功后进入网络层协议阶段；认证失败则转入链路终止阶段。

#### 2.5.4 网络层协议阶段（Network-Layer Protocol）

在此阶段，每个网络层协议通过各自的 NCP 进行配置。例如，IPCP 用于配置 IP 协议参数（如 IP 地址分配、DNS 服务器地址等）。NCP 协商成功后，PPP 链路进入数据传输阶段，可以传输网络层数据。

#### 2.5.5 链路打开阶段（Link Open）

链路已建立，数据正常传输。在此阶段，LCP 可以发送 Echo-Request 和 Echo-Reply 报文来测试链路的连通性。

#### 2.5.6 链路终止阶段（Link Terminate）

链路可以被任何一方主动终止（发送 LCP Terminate-Request），也可能因认证失败、链路质量下降等原因终止。终止后返回链路不可用阶段。

### 2.6 PPP 的认证协议

#### 2.6.1 PAP（Password Authentication Protocol）

PAP（密码认证协议）由 RFC 1334 定义，是一种简单的两次握手认证协议。

**PAP 的认证过程：**

1. 被认证方发送认证请求，包含用户名和密码（明文传输）。
2. 认证方检查用户名和密码的正确性，返回认证成功（Authenticate-Ack）或认证失败（Authenticate-Nak）。

**PAP 的特点：**
- 认证过程简单，仅需两次握手。
- **密码以明文方式传输**，安全性低。
- 认证只在链路建立时进行一次，之后不再验证。

#### 2.6.2 CHAP（Challenge-Handshake Authentication Protocol）

CHAP（挑战握手认证协议）由 RFC 1994 定义，是一种三次握手认证协议，安全性高于 PAP。

**CHAP 的认证过程：**

1. **挑战（Challenge）**：认证方生成一个随机数（挑战值），连同自己的主机名发送给被认证方。
2. **响应（Response）**：被认证方根据认证方的主机名查找对应的密码（密钥），将密码和挑战值一起作为输入，通过 MD5 哈希算法计算出一个哈希值。被认证方将哈希值连同自己的主机名发送给认证方。
3. **确认（Success/Failure）**：认证方也用同样的方法（自己保存的密码和发出的挑战值计算 MD5）计算哈希值，与被认证方发来的哈希值进行比较。如果一致，返回认证成功（Success）；否则返回认证失败（Failure）。

**CHAP 的特点：**
- **密码不以明文传输**，而是通过 MD5 哈希传输，安全性高。
- 使用随机挑战值，防止重放攻击。
- 可以在链路建立后周期性地重复认证，进一步保证安全。
- 认证方和被认证方需要预先共享密钥（密码）。

### 2.7 PPPoE（PPP over Ethernet）

PPPoE 是将 PPP 协议封装在以太网帧中传输的协议，由 RFC 2516 定义。PPPoE 广泛用于宽带接入场景（如 ADSL 拨号上网）。

PPPoE 的优势在于：它结合了以太网的普及性和 PPP 的认证、计费功能。ISP（互联网服务提供商）可以通过 PPPoE 对用户进行身份认证和 IP 地址分配，实现按用户计费。

PPPoE 的工作过程分为两个阶段：
1. **发现阶段（Discovery Stage）**：客户端通过广播 PADI（PPPoE Active Discovery Initiation）报文寻找接入集中器（AC），AC 回复 PADO，客户端选择 AC 后发送 PADR，AC 回复 PADS，建立 PPPoE 会话。
2. **PPP 会话阶段（PPP Session Stage）**：在 PPPoE 会话上进行标准的 PPP 协商（LCP、认证、NCP）和数据传输。

## 三、高级数据链路控制 HDLC

### 3.1 HDLC 概述

HDLC（High-level Data Link Control，高级数据链路控制）是国际标准化组织（ISO）制定的面向比特的数据链路层协议，基于 IBM 公司的 SDLC（Synchronous Data Link Control）协议发展而来。HDLC 标准由 ISO 3309（帧结构）和 ISO 4335（规程要素）等定义。

HDLC 的主要特点：
- **面向比特**：数据传输以比特为单位，帧定界使用比特模式 `01111110`，通过比特填充实现透明传输。
- **同步传输**：数据以同步方式传输，收发双方使用同一时钟。
- **支持全双工**：可以同时进行双向数据传输。
- **支持差错控制和流量控制**：通过帧序号和确认机制实现。

### 3.2 HDLC 的站类型和数据传输模式

#### 3.2.1 HDLC 的站类型

HDLC 定义了三种类型的站：

1. **主站（Primary Station）**：负责控制链路的操作，发送命令帧，接收响应帧。主站对链路进行管理。
2. **从站（Secondary Station）**：在主站的控制下操作，接收命令帧，发送响应帧。从站受主站控制。
3. **复合站（Combined Station）**：兼具主站和从站的功能，既能发送命令也能发送响应。

#### 3.2.2 HDLC 的数据传输模式

HDLC 定义了三种数据传输模式（操作模式）：

1. **正常响应模式（NRM, Normal Response Mode）**：
   - 用于非平衡配置（一个主站，多个从站）。
   - 从站只有在收到主站的允许后才能发送数据。
   - 适用于多点链路。

2. **异步响应模式（ARM, Asynchronous Response Mode）**：
   - 用于非平衡配置。
   - 从站不需要等待主站的允许就可以发送数据。
   - 较少使用。

3. **异步平衡模式（ABM, Asynchronous Balanced Mode）**：
   - 用于平衡配置（双方都是复合站）。
   - 每个复合站都可以平等地发起数据传输，不需要等待对方允许。
   - 全双工通信。
   - 是最常用的模式，广泛应用于点到点链路。X.25 协议的数据链路层 LAPB 就采用 ABM 模式。

### 3.3 HDLC 的帧格式

HDLC 的帧格式如下：

```
+------+------+------+------+----------+------+
| 标志  | 地址  | 控制  | 数据  | FCS       | 标志  |
| 8位  | 8位  | 8位  | 可变 | 16/32位   | 8位  |
+------+------+------+------+----------+------+
```

各字段说明：

- **标志字段（Flag, 8 位）**：值为 `01111110`（`0x7E`），用于帧定界。同一标志字段既可作为前一帧的结束标志，也可作为后一帧的开始标志。

- **地址字段（Address, 8 位，可扩展）**：在非平衡配置中，表示从站地址（命令帧）或发送该帧的从站地址（响应帧）。在平衡配置中，表示复合站的地址。地址字段可扩展为多字节（扩展寻址）。

- **控制字段（Control, 8 位，可扩展）**：用于标识帧的类型、帧序号和其他控制信息。根据控制字段的格式，HDLC 帧分为三种类型（详见下文）。

- **信息字段（Information, 可变长度）**：要传输的数据。只有 I 帧和部分 U 帧才有信息字段。

- **FCS 字段（Frame Check Sequence, 16 或 32 位）**：帧校验序列，使用 CRC 校验。通常使用 CRC-16，生成多项式为 x¹⁶ + x¹² + x⁵ + 1。

### 3.4 HDLC 的三种帧类型

根据控制字段的格式，HDLC 帧分为三种类型：

#### 3.4.1 信息帧（I 帧, Information Frame）

I 帧用于传输用户数据，同时携带流量控制和差错控制信息。

控制字段格式（8 位）：

```
| 0 | N(S) | P/F | N(R) |
| 1位| 3位  | 1位 | 3位  |
```

- **第 1 位为 0**：表示这是一个 I 帧。
- **N(S)（3 位）**：发送序号，表示当前发送的帧的编号。
- **P/F（Poll/Final, 1 位）**：询问/终止位。主站发送时为 P（Poll，询问），从站发送时为 F（Final，终止）。P=1 表示主站请求从站响应；F=1 表示从站发送的最后一帧。
- **N(R)（3 位）**：接收序号，表示期望收到的下一帧的编号，同时表示对 N(R)-1 及之前所有帧的累积确认。

当使用扩展模式（模 128）时，N(S) 和 N(R) 各扩展为 7 位，控制字段变为 16 位。

#### 3.4.2 监控帧（S 帧, Supervisory Frame）

S 帧用于流量控制和差错控制，不携带用户数据。

控制字段格式（8 位）：

```
| 1 | 0 | Type | P/F | N(R) |
| 1位|1位| 2位  | 1位 | 3位  |
```

- **前两位为 10**：表示这是一个 S 帧。
- **Type（2 位）**：监控帧的类型，有四种：
  - `00`：**RR（Receive Ready, 接收就绪）**——表示已准备接收，确认 N(R)-1 及之前的帧。用于正常确认。
  - `01`：**RNR（Receive Not Ready, 接收未就绪）**——表示忙，暂时不能接收，确认 N(R)-1 及之前的帧。用于流量控制（暂停发送）。
  - `10`：**REJ（Reject, 拒绝）**——请求重传从 N(R) 开始的所有帧（后退 N 帧重传）。
  - `11`：**SREJ（Selective Reject, 选择拒绝）**——请求只重传编号为 N(R) 的那一帧（选择重传）。
- **P/F**：同 I 帧。
- **N(R)**：接收序号，含义取决于帧类型。

#### 3.4.3 无编号帧（U 帧, Unnumbered Frame）

U 帧用于提供附加的链路控制功能，如建立、断开链路等。U 帧不携带序号。

控制字段格式（8 位）：

```
| 1 | 1 | Type | P/F | Type |
| 1位|1位| 2位  | 1位 | 3位  |
```

- **前两位为 11**：表示这是一个 U 帧。
- **Type（5 位，分两部分）**：无编号帧的类型编码，定义了不同的命令和响应。常见的 U 帧包括：
  - **SABM/SABME（Set Asynchronous Balanced Mode / Extended）**：设置异步平衡模式（正常/扩展），用于建立链路。
  - **SNRM/SNRME**：设置正常响应模式（正常/扩展）。
  - **DISC（Disconnect）**：断开链路。
  - **UA（Unnumbered Acknowledgment）**：无编号确认，对 SABM、DISC 等命令的确认。
  - **DM（Disconnected Mode）**：断开模式响应。
  - **FRMR（Frame Reject）**：帧拒绝，表示收到了无法处理的帧。
  - **UI（Unnumbered Information）**：无编号信息帧，可携带数据但不保证可靠传输。

### 3.5 HDLC 的数据传输过程

以异步平衡模式（ABM）为例，HDLC 的数据传输过程如下：

1. **建立链路**：一方发送 SABM 命令请求建立链路，另一方回复 UA 确认。链路建立后，双方可以开始数据传输。

2. **数据传输**：双方通过 I 帧交换数据，每个 I 帧携带 N(S) 和 N(R) 序号。收到正确的 I 帧后，可以发送 RR 帧进行确认。如果需要流量控制，发送 RNR 帧。如果检测到差错，可以发送 REJ 或 SREJ 请求重传。

3. **断开链路**：一方发送 DISC 命令请求断开链路，另一方回复 UA 确认。链路断开后，回到初始状态。

### 3.6 HDLC 的特点总结

- 面向比特，同步传输，传输效率高。
- 支持三种帧类型（I 帧、S 帧、U 帧），功能丰富。
- 支持全双工通信和多种数据传输模式。
- 提供完善的流量控制和差错控制机制（后退 N 帧或选择重传）。
- 使用 CRC 进行差错检测。
- 协议较复杂，主要用于专用网络和电信网络。
- 不支持认证功能（这是与 PPP 的重要区别）。

## 四、PPP 与 HDLC 的对比

### 4.1 协议设计理念

| 对比项目 | PPP | HDLC |
|---------|-----|------|
| 制定组织 | IETF（RFC 1661） | ISO（ISO 3309/4335） |
| 设计目标 | 互联网多协议接入 | 通用数据链路控制 |
| 面向对象 | 面向字符（异步）/ 面向比特（同步） | 面向比特（同步） |
| 适用场景 | 互联网拨号接入、宽带接入、路由器互联 | 专线、电信网络、X.25 等 |

### 4.2 帧格式对比

| 对比项目 | PPP | HDLC |
|---------|-----|------|
| 标志字段 | 0x7E（1 字节） | 0x7E（1 字节） |
| 地址字段 | 固定 0xFF（1 字节） | 表示站地址（可扩展） |
| 控制字段 | 固定 0x03（1 字节） | 可变，区分三种帧类型 |
| 协议字段 | 有（2 字节，标识上层协议） | 无 |
| 信息字段 | 有 | 有（I 帧和部分 U 帧） |
| FCS | 16 或 32 位 CRC | 16 或 32 位 CRC |

PPP 增加了**协议字段**，用于标识封装的上层协议，这使得 PPP 能够支持多种网络层协议的复用。HDLC 没有协议字段，通常通过预先约定或通过其他机制来区分上层协议。

### 4.3 功能特性对比

| 功能 | PPP | HDLC |
|------|-----|------|
| 差错检测 | 有（FCS/CRC） | 有（FCS/CRC） |
| 差错纠正 | 无（丢弃错误帧） | 有（重传机制） |
| 流量控制 | 无 | 有（RR/RNR） |
| 认证 | 有（PAP/CHAP） | 无 |
| 多协议支持 | 有（协议字段） | 无（需额外约定） |
| 链路协商 | 有（LCP） | 有（U 帧命令） |
| 网络层配置 | 有（NCP） | 无 |
| 序号和确认 | 默认无（可选） | 有（I 帧 N(S)/N(R)） |

### 4.4 关键区别总结

1. **多协议支持**：PPP 通过协议字段可以同时支持多种网络层协议；HDLC 没有协议字段，一般只支持一种网络层协议（除非使用扩展）。

2. **认证功能**：PPP 支持 PAP 和 CHAP 认证，适用于需要用户身份验证的接入场景；HDLC 不支持认证。

3. **可靠性**：HDLC 提供差错纠正和流量控制功能，是可靠的链路协议；PPP 默认不提供差错纠正和流量控制（只做差错检测），可靠性交由上层协议处理。不过 PPP 也可以通过多链路 PPP（MLPPP）等扩展来提供额外的功能。

4. **灵活性**：PPP 具有更强的灵活性，支持链路参数协商（LCP）和网络层配置（NCP），可以动态分配 IP 地址等；HDLC 的配置相对固定。

5. **应用场景**：PPP 广泛用于互联网接入（拨号、PPPoE）、路由器之间的链路等；HDLC 主要用于专线连接、电信网络中的数据链路控制等。

6. **传输模式**：PPP 支持异步和同步传输；HDLC 仅支持同步传输。

## 参考答案

### 选择题答案

**1. C。** PPP 协议由三个部分组成：PPP 的封装方式、链路控制协议 LCP 和网络控制协议 NCP。介质访问控制（MAC）是以太网等局域网协议的子层，不属于 PPP 的组成部分。PPP 是点对点协议，不需要介质访问控制。

**2. C。** CHAP 使用随机挑战值（Challenge），被认证方将密码和挑战值一起进行 MD5 哈希后传输，密码不以明文传输。CHAP 是三次握手认证协议，不是两次。CHAP 可以在链路建立后周期性地重复认证，不仅限于一次。因此选项 C 正确。

**3. A。** HDLC 中，信息帧（I 帧）用于传输用户数据，其控制字段包含发送序号 N(S) 和接收序号 N(R)，同时携带流量控制和差错控制信息。监控帧（S 帧）用于流量控制和差错控制但不携带用户数据；无编号帧（U 帧）用于链路管理，不携带序号；HDLC 中没有"确认帧"这一类型。

### 简答题答案

**1.**

PPP 协议的链路建立过程经历以下几个阶段：

（1）**链路不可用阶段（Link Dead）**：初始状态，物理层尚未就绪。当物理层报告链路已建立时，进入下一阶段。

（2）**链路建立阶段（Link Establishment）**：双方通过 LCP 交换配置报文，协商链路参数（如 MRU、认证协议、魔术字等）。LCP 协商成功后，根据配置决定是否进入认证阶段。

（3）**认证阶段（Authentication）**：如果 LCP 协商中要求认证，则在此阶段进行身份验证。可使用 PAP（两次握手，明文密码）或 CHAP（三次握手，MD5 哈希）。认证成功进入下一阶段，失败则转入链路终止。

（4）**网络层协议阶段（Network-Layer Protocol）**：通过各自的 NCP 配置网络层协议参数。例如，IPCP 可以协商分配 IP 地址、DNS 等。NCP 配置成功后进入链路打开阶段。

（5）**链路打开阶段（Link Open）**：链路已建立，正常传输数据。可以通过 LCP Echo 报文测试链路连通性。

（6）**链路终止阶段（Link Termination）**：当任一方请求终止、认证失败或链路故障时，发送 LCP Terminate-Request 终止链路，返回链路不可用状态。

**2.**

帧格式方面的主要区别：

- **协议字段**：PPP 有 2 字节的协议字段，标识封装的上层协议（如 IP、LCP、IPCP 等），支持多协议复用；HDLC 没有协议字段。
- **地址字段**：PPP 的地址字段固定为 0xFF（广播），因为 PPP 是点对点链路，不需要寻址；HDLC 的地址字段表示站地址，可扩展。
- **控制字段**：PPP 的控制字段固定为 0x03（无编号帧），默认不使用序号；HDLC 的控制字段可变，区分 I 帧、S 帧、U 帧，携带序号和控制信息。
- **透明传输**：PPP 在异步链路上使用字节填充，在同步链路上使用比特填充；HDLC 使用比特填充。

功能特性方面的主要区别：

- **可靠性**：HDLC 提供差错纠正和流量控制（通过帧序号、RR/RNR/REJ 等），是可靠链路协议；PPP 默认只做差错检测（FCS），不做纠错和流量控制，可靠性交给上层（如 TCP）。
- **认证**：PPP 支持 PAP 和 CHAP 认证；HDLC 不支持认证。
- **多协议支持**：PPP 通过协议字段支持多种网络层协议；HDLC 需要通过额外约定。
- **链路协商**：PPP 通过 LCP 动态协商链路参数，通过 NCP 配置网络层（如动态分配 IP 地址）；HDLC 通过 U 帧命令进行链路管理，配置相对固定。
- **传输模式**：PPP 支持异步和同步传输；HDLC 仅支持同步传输。
- **应用场景**：PPP 用于互联网接入（拨号、PPPoE）、路由器互联等；HDLC 用于专线、电信网络等。
